# Roam 紧凑双语字幕

> **0.5.0-beta.4 — Draft 预览版，非稳定版。** 按用户明确要求更新到既有 shorthand。本次只优化 YouTube 字幕请求、取消和缓存，不增加其他功能。59 项 Node 测试通过；本版浏览器回归及真实双语验收尚未完成。本机获取目标字幕时曾遇到 YouTube 429 限流，减少请求不等于解除上游限制；获取失败不会启动重复字幕遮罩。

## 这版的界面

- 双语入口是**视频下方原生工具栏里的一个图标**，不再占用画面右上角。
- 字幕只有**上下两行**：上面英文一行，下面译文一行。原字幕中的换行会接起来，横向展开。
- 两行紧挨着，**共用一个不透明背景**，不保留两块分离的字幕框。
- 设置只保留**开启/关闭、译文语言、字号**。自定义 API、模型、密钥、配对码、服务地址、导入和其他高级表单已移除。
- 目标语言列表来自当前 YouTube 视频的字幕元数据，包含该视频可用的日语、中文、法语等选项，不依赖写死的少量语言。
- 字号同时作用于两行。长句先用足视频宽度；仍放不下时会缩小，不拆成四行，也不省略文字。

## 单一渲染路径

英文与目标语言字幕分别由本机服务按当前视频实际提供的语言下载，并按各自的真实时间轴索引；插件只渲染这两条轨道，不调用 AI 翻译 API，也不从无障碍树取字幕或遮罩原生字幕。

显示前插件会请求关闭 YouTube 原生 CC，并通过本机只读桥确认同一视频框内的 `Subtitles/CC turned off` 状态。确认前、CC 为开或状态未知时，叠层始终隐藏，以免出现原生中文与双语叠加。下载失败前不会操作原生 CC。退出双语时先隐藏自己的字幕，再恢复本实例曾确认开启并主动关闭的原生 CC；不显示样例、假译文或旧内容。

当前已知 `zh-Hans` 的真实下载仍可能被 YouTube/yt-dlp 拒绝（例如 429）。这是明确失败状态，不代表双语可用；不会回退到浏览器取词、原生翻译轨道或其他绕过路径。

## 本次借鉴的范围

参考 [FluentRead 视频字幕说明](https://read.thinkstu.com/guide/video-subtitles)及其 [YouTube 桥入口](https://github.com/FluentRead/FluentRead/blob/4cc7cf8b949f293d3b27cd66d7885ebc47949b88/entrypoints/youtubeBridge.content.ts)，独立实现请求合并、缓存复用、失败退避和旧结果隔离，没有复制其 GPL 源码。

- 相同请求共用一个任务；某个调用方取消，不会取消其他仍在等待的调用方。不同下载串行排队，缓存命中不受排队影响。
- 首次同时需要英文与译文时，用一次 yt-dlp 提取下载两条轨道，避免分别重复提取视频信息。成功的轨道可复用，缺失译文仍明确失败。
- 本机队列满使用独立的 503；只有实际上游限流才返回 `YOUTUBE_RATE_LIMITED` / 429。遇到真实 429，本机保护性暂停新字幕请求 60 秒，不自动重试；不保证 YouTube 届时恢复。
- 关闭设置、关闭字幕或换视频会正确取消不再需要的请求，旧元数据不能覆盖新视频；超时不再误报为服务未连接。

FluentRead 的 MAIN-world 请求旁路和原生字幕 DOM 隐藏依赖浏览器扩展权限，不能直接用于当前 Roam 桌面跨域 iframe；其缺少人工目标字幕时的外部翻译路线也未引入。网页、PDF、X、会议、词典、学习模式和 ASR 均不在本次范围。

## 当前支持范围与隐私

这个同框实现目前针对 **macOS 的 Roam Research 桌面版**。需要已安装的 Node.js 22.10+、yt-dlp，以及已运行并已有辅助功能权限的 CuaDriver。本项目不会自动安装软件、申请/更改权限、解锁屏幕、启动录制或操作其他应用。

开启双语时，本机只读桥仅用于确认指定 Roam 窗口中、与**当前视频标题和位置相符**的 YouTube CC 开关状态；不提取字幕文本。它不返回无障碍树、笔记、窗口标题或截图，也不通过图谱 API 读取或修改笔记。

- 状态读取只允许当前登录 OS 用户、且来自 Roam 桌面进程的本机连接；继续检查 Host、Origin、视频 ID、标题和视频范围。
- 不接受调用方指定任意 PID、窗口或工具动作。
- 读取组件只使用现有只读能力，不截图、不录制；发现工具处于录制状态时会停止读取。
- 关闭双语、打开设置、视频离开可视区域或页面隐藏时不读取状态。
- 锁屏、CC 控件暂时不存在或标签未知时不会把它当作关闭，也不会显示叠层。

## Draft 试用

1. 使用本版源码运行 `start.command`，或在项目目录执行 `npm start`。从 0.4 升级时须先停止旧服务，再启动新版；本版使用服务 API v3。不用配置任何 AI API。
2. 在 Roam Depot 中重新加载原 shorthand 的扩展，使用视频下方工具栏里的双语图标。
3. 开启双语，选择目标语言，调整字号，点“完成”。若 YouTube 返回 429，请稍后再试，不要连续重试。

原 shorthand 保留：

```text
404KSG+roam-youtube-bilingual+1509
```

**本次更新仅发布到既有 Draft 预览，不代表真实桌面验收通过。** PR 保持 Draft，不合并、不正式上架、不创建 Release。YouTube 目标字幕下载失败或无法确认原生 CC 关闭时，插件保持字幕叠层隐藏。

## 设置说明

- 原文固定为英文，位于第一行。
- 译文语言由当前视频实际提供的语言列表决定。
- 字号范围 12–36 px，表示首选字号；超长句会按可用宽度适配。
- 切换目标语言不会重新下载英文；会下载并验证所选语言的实际字幕轨道。
- 设置是即时生效的，“完成”关闭设置窗口。

需要保留双语的全屏，可从 Roam 命令面板运行“**YouTube 双语字幕：双语全屏**”。YouTube 自带 iframe 全屏/PiP 不包含插件层。

## 本机服务

默认地址为 `http://127.0.0.1:17321`。不需要 `.env`，也没有开机启动或定时任务。若已有 `.env`，仅读取 `PORT`、`YT_DLP_PATH`、`CUA_DRIVER_PATH` 三个运行参数，不读取旧的 API 配置。

语言列表、英文和目标字幕都通过只读接口获取，并按 `videoId:language` 缓存；桌面 CC 状态接口额外验证连接的 OS 用户。所有自定义 AI 翻译接口已删除。

## 开发

```bash
./build.sh
```

- `src/extension.mjs`：底部图标、精简设置、双轨时间索引和 CC 渲染门禁。
- `src/surface.mjs`：视频叠层和双语全屏。
- `server/video-info.mjs`：当前视频的英文轨道与可用语言。
- `server/caption-reader.mjs`：严格限定的本机只读 CC 状态确认。
- `test/unified-fixture.html`：纯本地测试页面，无真实视频内容。

本地截图和临时日志只在被 Git 排除的 `artifacts/` 中。停用扩展会移除自己的图标、字幕叠层和样式，保留原生视频及工具栏图标。
